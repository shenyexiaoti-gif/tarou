## 1. 前提の転換：キーワードからトピックへ

単一キーワードで1記事を作る時代は終わっている。検索エンジンはクエリ単位ではなく**エンティティ（実体）とトピックの網羅度**でサイトを評価する。狙うのは「このテーマならこのサイト」という状態（トピカルオーソリティ）。

- 1キーワード＝1記事 ではなく、**1トピック＝1クラスタ（親記事＋子記事群）**
- クラスタ化された記事群は単発記事より流入が伸び、順位も長持ちするという観測が業界横断で共有されている
- ただし「網羅のための薄い記事」を量産すると逆効果（→ `08-spam-penalty.md` の scaled content abuse）

## 2. 検索意図の分類

古典的な4分類（Know / Go / Do / Buy）は入口。実務では以下の粒度で判定する。

| 意図 | クエリ例 | 求められるページ形式 |
|---|---|---|
| 即答（Short fact） | 「INP 基準値」 | 冒頭で結論1文。表・定義 |
| 理解・学習（Know） | 「テクニカルSEOとは」 | 定義→構造→具体例→次の一歩 |
| 手順（Do / How） | 「Search Console 登録 方法」 | 番号付き手順＋スクショ＋つまずき対処 |
| 比較（Compare） | 「A B 違い」 | 比較表→用途別の推奨→判断基準 |
| 選定・購入（Buy） | 「SEOツール おすすめ」 | 選定基準→候補→料金→誰に向くか |
| 指名（Go / Navigational） | 「◯◯社 ログイン」 | 該当ページに最短で送る |
| 結果・帰結（Consequence） | 「被リンク購入 どうなる」 | リスク→実例→回避策 |
| 意見・体験（Opinion） | 「◯◯ 使ってみた 感想」 | 一次体験。UGC（Reddit/知恵袋/X）が強い領域 |

**判定は推測でやらない。実際に検索して上位10件の型を数える。** 上位が比較表なら比較表を求められている。ここを外すと他が全部無駄になる。

**混合意図に注意：** 上位に複数の型が混在するクエリは、意図が割れている＝どちらかに寄せるか、1記事内で両方に答える設計にする。

## 3. キーワードの発掘手順

1. **シード（種）を出す**：自社の商品・サービス、顧客が実際に使う言葉、営業やサポートに来る質問
2. **サジェスト／関連検索**：Googleサジェスト、関連する質問（PAA）、ページ下部の関連検索
3. **Search Consoleの掘り起こし**：既に表示されているが順位が低い（11〜30位）クエリ＝最短の伸びしろ
4. **競合のカバー範囲**：競合が取れていて自分が取れていないトピック（コンテンツギャップ）
5. **顧客の声**：問い合わせ、レビュー、SNS、コミュニティの生の言葉。ツールに出ない言い回しが取れる
6. **AI検索でのプロンプト**：ユーザーはAIに対して長文・会話的に聞く。「〜したいんだけどどれがいい？」型の質問も収集対象（→ `06-ai-search-geo.md`）

## 4. キーワードの評価軸

| 軸 | 見方 |
|---|---|
| 検索ボリューム | 目安。ゼロボリュームでも成約直結なら価値がある |
| 検索意図の一致度 | 自社が答えを持っているか。持っていないなら書かない |
| 難易度 | 上位のドメインの強さ・被リンク・情報の厚み。**「勝てるか」より「勝つのに何が必要か」で見る** |
| ビジネス貢献度 | CVまでの距離。集客KWとCV直結KWを混ぜて評価しない |
| SERPの奪われ度 | AI Overview／強調スニペット／広告／動画枠で、クリックが残るか |
| 鮮度要求 | 毎年更新が必要か（QDF：最新性が求められるクエリ） |

**優先順位の式（実務の目安）:** ビジネス貢献度 × 意図一致度 ÷ 難易度。ボリュームは最後に効かせる。

## 5. トピッククラスタ設計

```
[ピラーページ] 「◯◯とは」網羅型・全体像
   ├─ [クラスタ] ◯◯のやり方
   ├─ [クラスタ] ◯◯ 費用
   ├─ [クラスタ] ◯◯ 失敗例
   └─ [クラスタ] ◯◯ ツール比較
```

- ピラーは全体像を高い視座で扱い、**全クラスタへリンクする**
- クラスタは1つの具体論を深く扱い、**必ずピラーへ戻すリンクを持つ**
- クラスタ同士も関連するもの同士でつなぐ（ハブ＆スポーク＋横のつながり）
- ピラーの分量は目安であって目的ではない。文字数を埋めるための冗長化は評価を下げる
- 設計時に**URL構造・パンくず・内部リンクを同時に決める**（後付けは崩れる）

## 6. 競合／SERP分析の手順

1. 対象クエリを**シークレットウィンドウ**で検索（パーソナライズを排除）。地域指定が必要なら明示
2. 上位10件について記録する：
   - ページ種別（記事／LP／比較／公式ドキュメント／UGC）
   - 見出し構成（何に答えているか）
   - 一次情報の有無（独自データ・実測・体験）
   - 更新日
   - ドメインの性質（メディア／事業者／個人／公的機関）
3. SERP機能を記録：AI Overview、強調スニペット、PAA、動画、画像、ローカルパック、ショッピング
4. **共通項＝必須要件**、**どこも答えていない問い＝勝ち筋**
5. 勝ち筋が見つからないクエリは、無理に取りに行かず優先度を下げる

## 7. カニバリゼーション（共食い）の検出と解消

同一意図の記事が複数あると、評価が分散して両方伸びない。

**検出:** GSCで同一クエリに対して複数URLが表示されている／狙いと違うURLが表示される。

**解消の判断:**
- 意図が同じ → 統合（強い方に寄せて301リダイレクト）
- 意図が微妙に違う → 見出しと導入で差を明確化し、相互リンクで役割分担を示す
- 一方が明確に劣化 → 削除＋リダイレクト（削除だけで放置しない）

## 8. 日本語キーワード特有の論点

- **表記ゆれ**：漢字／ひらがな／カタカナ／英字／半角全角。検索需要が大きい表記を本文とタイトルに採用し、他は自然な範囲で本文に含める（不自然な羅列はしない）
- **助詞の省略**：「SEO やり方」のような助詞なしクエリが主流。見出しは自然な日本語のまま、キーワードの語を含める
- **検索エンジンのシェア**：日本ではGoogleが支配的で、Yahoo!はGoogleの検索技術を利用しているため実質的に対策は共通。BingはWindows／Edge環境で一定のシェアがあり、**AI検索（Copilot等）の基盤でもあるためインデックス状況は確認しておく**（Bing Webmaster Toolsの登録は低コスト）
- **検索行動の分散**：若年層はInstagram・TikTok・YouTube・AIチャットで探す。BtoCでは検索エンジン以外の入口設計も併せて考える
- 数値・シェアは変動が速い。断定する前に必ず最新を確認する（SKILL.md §3）
