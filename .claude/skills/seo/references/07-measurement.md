## 1. KPIの設計

**「順位」を最終KPIにしない。** 順位はコントロール可能な中間指標であって成果ではない。

```
[最終成果] 売上 / 問い合わせ / 登録
     ↑
[事業KPI] CV数、CVR、CPA相当額、指名検索数
     ↑
[流入KPI] オーガニックセッション、AI経由セッション、クリック数
     ↑
[可視性KPI] 表示回数、平均順位、AI引用率、対象KWのカバー率
     ↑
[施策KPI] 公開本数、リライト本数、被リンク獲得数、技術課題の解消数
```

**階層を飛ばして報告しない。** 「順位が上がりました」だけの報告は価値がない。上の階層にどう効いたかまで書く。

**BtoBやCVが少数の場合**：CV数だけでは変動が大きいので、マイクロコンバージョン（資料DL、料金ページ到達、比較記事の読了）を併用する。

## 2. Search Console（GSC）の使い方

**最優先で見るレポート**

| レポート | 見る目的 |
|---|---|
| 検索パフォーマンス | クエリ・ページ・国・デバイス別のクリック／表示／CTR／平均順位 |
| インデックス作成（ページ） | インデックス済み／未登録の理由別内訳。**技術事故の一次検知** |
| サイトマップ | 送信URL数と検出数の乖離 |
| ウェブに関する主な指標 | Core Web Vitalsの実測評価（**ここが正**） |
| 拡張（構造化データ） | 型別のエラー・警告 |
| リンク | 内部・外部リンクの状況 |
| 手動による対策 / セキュリティの問題 | **順位下落時に真っ先に見る**（→ `08-spam-penalty.md`） |
| AI検索関連レポート | AI Overviews / AI Mode での表示状況（項目は追加・変更が続くため最新を確認） |

**実務のクエリ分析（宝の山）**
1. 表示回数が多くCTRが低い → タイトル・ディスクリプション改善の対象
2. 平均順位11〜20位 → **最も投資効率が高いリライト候補**
3. 意図と違うページが表示されている → カニバリまたは内容のズレ
4. 表示はあるが自社が想定していないクエリ → 新規記事のネタ、または既存記事に節を追加
5. 期間比較（前年同期・前月）で下落したクエリ群 → 原因の切り分けに使う

**注意点**
- 平均順位は表示された全ケースの平均。パーソナライズ・地域・デバイスで揺れる
- データには反映遅延がある（おおむね2〜3日）
- クエリはプライバシー上、一部が非表示（合計値と個別クエリの合計は一致しない）
- **AI要約内での引用は、表示回数の扱いが従来と異なる。クリックに直結しない表示が増える前提で読む**

## 3. GA4の使い方

- **オーガニック流入**：`session_default_channel_group = Organic Search`
- **ランディングページ別**の成果を見る（セッション、エンゲージメント率、CV）
- **コンバージョン（キーイベント）を必ず設定する**。設定していないGA4は意味がない
- 探索レポートで「オーガニック × ランディングページ × キーイベント」の表を作り、記事単位のROIを見る
- Search Consoleとの連携を有効化（クエリとGA4の行動データを突き合わせる）
- **AI経由流入のセグメント**を作る（§4）

## 4. AI検索の可視性測定

現状、完全な測定手段は存在しない。**3系統を組み合わせる。**

**(a) GSC**：AI検索関連レポートで表示状況を追う。クリックの粒度には制約があるため、表示回数トレンドとして扱う。

**(b) GA4の参照元セグメント**：以下を含む参照元を「AI」チャネルとしてまとめる。
```
chatgpt.com / chat.openai.com / perplexity.ai / gemini.google.com
claude.ai / copilot.microsoft.com / bing.com（Copilot経由）
```
※参照元は増減する。定期的に「参照元/メディア」の一覧を見て新顔を拾う。

**(c) 手動プロンプト監査（最も実態に近い）**
1. 自社にとって重要な質問を20〜30個、固定セットで用意する（購買検討・比較・課題認識の3層）
2. 月1回、各AIに同じ質問を投げる
3. 記録する：自社が言及されたか／引用URLは何か／競合は誰が出たか／回答内の記述は正確か
4. 追う指標：**引用率**（自社が出た質問の割合）、**競合との相対**、**誤情報の有無**

誤った記述をAIがしている場合は、その情報源を特定して自社サイトと外部の記述を修正する（放置すると再生産される）。

## 5. 順位計測

- 計測ツールは「傾向を見る道具」。絶対値を信用しすぎない（パーソナライズ・地域・デバイスで変わる）
- 主要KWを20〜50個に絞って定点観測する。全KWを追うと変動に振り回される
- **順位より「そのクエリでクリックが取れているか」を見る**
- 記録：計測日、KW、順位、URL、SERP機能の有無（AI Overviewの有無は必ず記録する）

## 6. レポートの型

```
1. サマリー（3行）
   - 今月何が起きたか / 何をしたか / 次に何をするか
2. 成果（事業KPI）
   - CV数、CVR、指名検索数。前月比・前年同月比
3. 流入（オーガニック・AI経由）
   - セッション、クリック数。増減の要因を1つずつ特定して書く
4. 可視性
   - 主要KWの順位変動、表示回数、AI引用率
5. 実施した施策と結果
   - 施策 → 対象URL → 実施日 → 現時点の変化
6. 課題と次アクション（優先順3つ）
   - 影響度×工数で並べる
7. 外部要因
   - コアアップデート、SERP仕様変更、季節性、競合の動き
```

**禁止事項:** 数字を並べただけのレポート。**必ず「なぜそうなったか」と「次に何をするか」を書く。**

## 7. 効果判定のルール

- **最短4週間、通常は3ヶ月**。SEOは反映が遅い
- コアアップデートのロールアウト中は判定を保留する（変動が施策由来か判別できない）
- **1回の変更で複数箇所をいじると原因が特定できない**。重要な検証は要素を分ける
- 季節性を必ず前年同月比で確認する
- 比較は「サイト全体」ではなく「変更したページ群」と「変更していないページ群」で行う（対照群を持つ）
- 負けを認める判定基準を先に決める（例：3ヶ月で順位が5位以上改善しなければ設計から見直す）
