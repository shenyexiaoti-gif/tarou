## 1. 診断フローチャート

```
相談が来た
 ├ 「順位が落ちた」「流入が減った」
 │    → 08-spam-penalty.md §1 の切り分けフロー（最優先）
 ├ 「これから記事を書く」
 │    → 01（KW設計）→ 02（構成）→ §2 公開前チェック
 ├ 「記事はあるが上がらない」
 │    → 07（GSCで原因特定）→ 02 §8（リライト手順）
 ├ 「サイト全体を見てほしい」
 │    → §4 サイト監査チェックリスト
 ├ 「インデックスされない」「表示が遅い」
 │    → 03-technical.md
 ├ 「AIに引用されたい」
 │    → まず土台（インデックス・E-E-A-T）を確認 → 06-ai-search-geo.md
 └ 「新しくサイトを作る」
      → §3 立ち上げチェックリスト
```

## 2. 記事の公開前チェックリスト

**意図と価値**
- [ ] 対象クエリを実際に検索し、上位10件の型を確認した
- [ ] 検索意図に対する答えが**冒頭2〜3文**にある
- [ ] 上位10件を全部読んだ人が、この記事から得る新しいものを一文で言える（Information Gain）
- [ ] 一次情報（実データ／実体験／独自検証）が入っている

**書式**
- [ ] タイトルにキーワードが自然に入り、内容と乖離していない
- [ ] メタディスクリプションを設定した
- [ ] H1は1つ、H2→H3の階層が飛んでいない
- [ ] 見出しだけ読んで内容が分かる
- [ ] 表・箇条書き・番号手順でスキャンできる
- [ ] 画像にalt属性、ファイルサイズを最適化した

**信頼（E-E-A-T）**
- [ ] 著者名・肩書・プロフィールへのリンクがある
- [ ] 公開日／更新日が表示されている
- [ ] 数値・事実に出典リンクがある（一次情報に当たった）
- [ ] YMYL領域なら監修・公的資料の裏付けがある
- [ ] 誇大表現・法規制（景表法・薬機法・ステマ規制）に触れる記述がない

**技術**
- [ ] URLが適切（短く、意味が分かる、公開後変えない）
- [ ] canonicalが自己参照
- [ ] `noindex` が付いていない
- [ ] 構造化データ（Article / BreadcrumbList など）を実装し、検証ツールを通した
- [ ] モバイルで表示崩れがない

**内部リンク**
- [ ] **既存の関連記事から、この新記事へのリンクを追加した**（忘れやすい最重要項目）
- [ ] この記事から関連記事・CV導線へリンクした
- [ ] アンカーテキストが具体的（「こちら」になっていない）

**AI検索**
- [ ] 見出しが質問文になっていて、直下で答え切っている
- [ ] 数値に単位・条件・時点が付いている
- [ ] 初期HTMLに本文が含まれる（JS依存でない）

**運用**
- [ ] 公開後、サイトマップに反映／GSCでURL検査＋インデックス登録をリクエストした
- [ ] 対象KW・公開日・初期順位を記録した
- [ ] （公開コンテンツなら）`masking-guard` を通した

## 3. 新規サイト立ち上げチェックリスト

- [ ] ドメイン決定（中古ドメインは履歴を必ず確認。期限切れドメインの不正使用に該当しない用途か）
- [ ] HTTPS化、www有無・末尾スラッシュの統一とリダイレクト
- [ ] Search Console・GA4・Bing Webmaster Tools の登録
- [ ] XMLサイトマップ生成と送信、robots.txtの設置と検証
- [ ] サイト構造の設計（トピッククラスタ、URL設計、パンくず）
- [ ] Organization / WebSite 構造化データ
- [ ] 運営者情報・プライバシーポリシー・お問い合わせ・著者プロフィールページ
- [ ] 404ページの整備、ソフト404の排除
- [ ] Core Web Vitalsの初期計測
- [ ] **公開前にテスト環境の `noindex` / Basic認証が本番に残っていないか確認**（事故の定番）

## 4. サイト監査チェックリスト（フル）

上の層から順に見る。**各項目に「影響度（高/中/低）」と「工数」を付けて優先順位化して報告する。**

**A. クロール**
- [ ] robots.txt の内容と誤ブロック
- [ ] サイトマップの正確性（200のURLのみ／正規URLのみ／lastmod）
- [ ] GSCクロール統計（レスポンスコード、応答時間の推移）
- [ ] 無限URL生成（パラメータ、絞り込み、カレンダー）
- [ ] リンク切れ、リダイレクトチェーン／ループ

**B. インデックス**
- [ ] インデックス作成レポートの除外理由の内訳
- [ ] 意図しない `noindex`
- [ ] canonicalの整合性（自己参照、矛盾したシグナル）
- [ ] 重複コンテンツ（http/https、www、パラメータ、タグページ、ページネーション）
- [ ] 薄いページ・自動生成ページの有無

**C. レンダリング**
- [ ] 初期HTMLに本文・内部リンクが含まれるか
- [ ] `<a href>` でリンクされているか
- [ ] CSS/JSがブロックされていないか

**D. 構造**
- [ ] 階層の深さ（重要ページが3クリック以内）
- [ ] 孤立ページの有無
- [ ] 内部リンクの分布（重要ページに集まっているか）
- [ ] アンカーテキストの質
- [ ] パンくずの実装

**E. ページ体験**
- [ ] GSCウェブに関する主な指標（LCP / INP / CLS）のURL群別評価
- [ ] モバイルでの表示・操作性
- [ ] 過剰なインタースティシャル

**F. コンテンツ**
- [ ] タイトル・ディスクリプションの重複・欠落
- [ ] カニバリゼーション
- [ ] 情報の陳腐化（古い数値・仕様・スクショ）
- [ ] E-E-A-Tシグナル（著者・運営者・出典・更新日）
- [ ] 棚卸し4分類（Keep / Improve / Merge / Remove）

**G. 構造化データ**
- [ ] コアセットの実装状況
- [ ] GSC拡張レポートのエラー・警告
- [ ] 実体と乖離したマークアップの有無

**H. 外部**
- [ ] 被リンクプロファイルの健全性
- [ ] 未リンク言及の有無
- [ ] 指名検索の推移

**I. リスク**
- [ ] 手動対策・セキュリティの問題の通知
- [ ] スパムポリシーに抵触する実装（→ `08-spam-penalty.md` §4）
- [ ] 法規制（景表法・薬機法・ステマ規制）

## 5. リライト前チェックリスト

- [ ] GSCで対象記事のクエリ・クリック・表示・CTR・順位を記録した（Before）
- [ ] 現在の上位10件を再観察し、**検索意図が変わっていないか**確認した
- [ ] 落ちている原因の仮説を1つに絞った（CTR／順位／意図ズレ／需要減）
- [ ] 何を足すか、**何を削るか**を決めた
- [ ] 内部リンクの見直し範囲を決めた
- [ ] 変更内容と日付を記録する場所を用意した
- [ ] 判定は最低4週間後と決めた

## 6. 緊急対応（順位急落）

**最初の30分でやること**
1. GSC「手動による対策」「セキュリティの問題」を確認
2. サイトが正常に表示されるか（HTTPS、DNS、5xx）を確認
3. `robots.txt` と主要ページの `noindex` / canonical を確認
4. GSCインデックス作成レポートで急減がないか確認
5. 下落の開始日・影響範囲を数字で特定
6. Googleのアップデート情報と日付を照合

**やらないこと**：原因不明のままサイトを大改修する／記事を大量削除する／被リンクを買う。

以降は `08-spam-penalty.md` §1 のフローへ。

## 7. サイトリニューアル／移行チェックリスト

**事前**
- [ ] 旧URL全件のリスト化（サイトマップ＋クロール＋GSC＋GA4で網羅）
- [ ] 流入・被リンクのある重要URLを特定
- [ ] 旧→新の**1対1マッピング表**を作成（まとめてトップに飛ばさない）
- [ ] 新サイトの構造化データ・メタ情報・内部リンクの設計
- [ ] 新環境の `noindex` / Basic認証の解除手順を明文化

**移行時**
- [ ] 301リダイレクトの一括設定と全件テスト
- [ ] 新サイトマップの生成・送信
- [ ] GSCのアドレス変更ツール（ドメイン変更時）
- [ ] canonical・hreflangの更新
- [ ] 計測タグの移設確認

**移行後**
- [ ] 2週間は毎日：インデックス数、エラー、404、順位、流入を監視
- [ ] 404が出たURLを即座にマッピングへ追加
- [ ] 1ヶ月・3ヶ月で移行前と比較

## 8. 月次運用ルーチン

| 頻度 | 作業 |
|---|---|
| 毎週 | GSCのエラー確認、主要KWの順位、公開記事への内部リンク追加 |
| 毎月 | クエリ分析（11〜20位の抽出）、リライト2〜3本、AI引用の手動監査（固定20〜30問）、レポート作成 |
| 四半期 | コンテンツ棚卸し、テクニカル監査、被リンク・言及の点検、KPIの見直し |
| 随時 | コアアップデート発表時の監視、競合の大きな動きの観察 |
