## 1. 下落の切り分けフロー

**原因を特定する前に施策を打たない。** 上から順に潰す。

```
Q1. GSC「手動による対策」に通知があるか
    YES → 手動対策（§2）。他の作業より最優先
    NO  ↓
Q2. GSC「セキュリティの問題」に通知があるか
    YES → ハッキング・マルウェア。即座に対応（サイト全体が飛ぶ）
    NO  ↓
Q3. 技術事故か（サイト全体 or 特定ディレクトリが一斉に落ちた）
    → noindex混入 / robots.txt / 5xx / SSL証明書切れ / DNS / canonical誤り
      / サイト移行のリダイレクト漏れ / CDN設定 / WAFがクローラを弾いている
    → GSCのインデックス作成レポートとURL検査で確認
    NO  ↓
Q4. 下落の日付がGoogleのアップデートと一致するか
    → コアアップデート / スパムアップデート の公表日と照合
    YES → §5
    NO  ↓
Q5. SERPの構造が変わったか
    → AI Overviewの出現、広告枠の増加、動画・ショッピング枠の追加
    → 順位は同じでもクリックが減る。この場合「順位対策」は効かない
    NO  ↓
Q6. 検索需要そのものが減ったか（表示回数も減っている）
    → Googleトレンド、前年同月比で確認。季節性か市場変化か
    NO  ↓
Q7. 競合が伸びたか
    → 上位のページを再観察。何を足してきたか、意図の解釈が変わっていないか
```

**必ず記録する:** 下落の開始日、影響範囲（全体／ディレクトリ／個別URL）、影響を受けたクエリの種類、デバイス差、地域差。

## 2. 手動対策（Manual Action）

人間の審査官による措置。GSCに通知が出る。**通知が出ていない下落を「ペナルティ」と呼ばない。**

主な種類:
- サイト全体からの不自然なリンク／サイトへの不自然なリンク
- 価値のない質の低いコンテンツ
- クローキング／不正なリダイレクト
- 隠しテキスト／キーワードの詰め込み
- **サイトの評判の不正使用**（他社ドメインを間借りした商用コンテンツ）
- 構造化データのスパム
- ユーザー生成スパム（コメント欄等の放置）
- ハッキングされたコンテンツ

**対応手順**
1. 通知の内容と対象範囲（サイト全体／一部）を正確に読む
2. 該当箇所を**全部**修正する（一部だけの修正は再申請で落ちる）
3. リンク由来なら：不自然なリンクの削除を依頼 → 削除できないものを否認ツールで否認 → **やった作業の記録を残す**
4. 再審査リクエストを送る。**何が問題で／何をどう直して／再発防止に何をしたかを具体的に書く**（言い訳と謝罪だけの文面は通らない）
5. 結果が出るまで数日〜数週間。落ちたら差分を修正して再提出

## 3. アルゴリズムによる評価低下

通知は出ない。再審査リクエストも存在しない。**改善してシステムが再評価するのを待つしかなく、数ヶ月かかることがある。**

見分け方：GSCに通知が無く、技術事故でもなく、アップデートの時期と一致する。

## 4. スパムポリシー一覧（要点）

| ポリシー | 内容 | 現場で起きがちな形 |
|---|---|---|
| **スケールされたコンテンツの不正使用** | 検索順位操作を主目的とした大量生成。**AI生成か人力かは問わない** | KW差し替えのテンプレ量産、他サイトの言い換え記事の大量公開 |
| **サイトの評判の不正使用** | 第三者が権威あるサイトの一部を借りて自社商用コンテンツを載せる | 大手メディアの「PR枠」に無関係な商材ページを量産 |
| **期限切れドメインの不正使用** | 中古ドメインを買い、無関係な内容で評価を流用 | オールドドメイン転用 |
| クローキング | 人間とクローラーに別の内容を見せる | UA判定での出し分け |
| 不正なリダイレクト | 検索結果からの流入を別ページに飛ばす | モバイルのみ別サイトへ |
| 隠しテキスト・キーワード詰め込み | 見えない文字、羅列 | 背景色と同色、CSSで隠す |
| リンクスパム | 売買、相互リンク、大規模な自演 | リンク購入、PBN |
| ドアウェイページ | 検索用の中身の薄い量産ページ | 地名だけ差し替えた同文ページ |
| 誤解を招く機能 | 存在しない機能を謳って集客 | ダウンロードできないツールページ |
| スクレイピング | 他サイトの複製 | RSS転載、翻訳しただけの記事 |
| 無断生成コンテンツ | 意味の通らない自動生成 | 機械翻訳の垂れ流し |

**判断基準:** 「これは検索エンジンのためにやっているか、ユーザーのためにやっているか」。前者ならリスク。

## 5. コアアップデートへの対応

Googleの公式見解は「**コアアップデートによる下落は、その特定のページに問題があることを意味するとは限らない。全体としてより良いコンテンツを評価するための見直しである**」。

**やること**
1. ロールアウト完了まで待つ（数週間かかる）。途中の変動で判断しない
2. 完了後、下落したページ群と維持したページ群の**差分**を洗い出す（トピック、意図、一次情報の有無、更新日、著者情報）
3. 自問リストで評価する:
   - 独自の情報・分析・調査を提供しているか
   - 主題を包括的に扱っているか（表面的な言い換えでないか）
   - 明らかに検索エンジン向けの構成になっていないか
   - 著者と運営者の情報が明確か
   - 読み終えて満足し、他を探し直す必要が無い内容か
   - タイトルは内容を誇張していないか
4. **一次情報の追加とE-E-A-Tシグナルの整備が、実務上の最有効手**（→ `02-content-eeat.md`）
5. 回復は次以降のアップデートのタイミングで起きることが多い。**数ヶ月単位で見る**

**やらないこと**：慌てて大量のページを削除する、記事を全部書き直す、被リンクを買う。パニック対応は事態を悪化させる。

## 6. 復旧の実務

```
1. 影響範囲を数字で特定（どのURL群が、いつから、どのクエリで、どれだけ）
2. 原因の仮説を1つに絞る（切り分けフローの結果）
3. 修正計画を作る（影響度×工数で優先順位）
4. 修正を実行。変更内容と日付を全部記録する
5. 手動対策なら再審査リクエスト。アルゴリズムなら待つ
6. 週次でGSCを確認。3ヶ月動きが無ければ仮説を見直す
```

**復旧しないケースも現実にある**。その場合は「同じサイトで別のトピックを立て直す」「新規に信頼性の高い資産を作る」方向に切り替える判断を、正直に伝える。

## 7. ネガティブSEO（他者による攻撃）の扱い

- Googleは「ほとんどのスパムリンクは自動的に無視される」としており、**過度に心配する必要はない**
- 否認ツールは**手動対策を受けている／明らかに自分で作った悪質なリンクがある**場合の道具。予防的な乱用は害になり得る
- 実際に多いのは「コピーサイトによる重複」「ハッキングによるスパムページの生成」。後者はセキュリティ問題として即対応
