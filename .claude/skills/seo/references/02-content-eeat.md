## 1. E-E-A-Tの実装

E-E-A-T＝Experience（経験）／Expertise（専門性）／Authoritativeness（権威性）／**Trust（信頼）**。
Trustが中心で、他の3つはTrustを支える要素。**評価はランキング要因そのものではなく、品質評価の枠組み**だが、これを満たす作りはアルゴリズムが拾う具体的シグナルと重なる。

| 要素 | ページ上でやること |
|---|---|
| Experience | 自分でやった証拠を置く。**撮影した写真、実測データ、日付入りの結果、失敗の記録**。「使ってみた」なら操作画面。ここが2026年に最も効く差別化 |
| Expertise | 執筆者名・肩書・実務歴・保有資格・関連実績を著者情報として明示。監修者を立てるならその根拠も |
| Authoritativeness | 外部からの言及・引用・受賞・取材実績・公的機関からのリンク（→ `05-offpage-local.md`） |
| Trust | 運営者情報／所在地／連絡先／プライバシーポリシー／料金の明示／出典リンク／公開日と更新日／訂正履歴。ECなら返品・支払い情報 |

**チェック:** そのページに「誰が・どんな根拠で・いつ書いたか」が書いてあるか。無ければE-E-A-T以前の問題。

## 2. YMYLの扱い

YMYL（Your Money or Your Life）＝健康・医療・金融・法律・安全・重要な生活判断など、誤情報が人生に実害を与える領域。定義は拡大傾向にある。

- 個人の体験談だけでは足りない。**一次資料（公的機関・査読論文・法令）へのリンク**を必須にする
- 有資格者の監修を入れる。監修者の実在性を確認できる形で示す
- 断定を避け、リスクと例外を明記する
- 「稼げる」「必ず治る」等の断定表現は使わない
- **BtoBでも金額・契約・雇用に関わる情報はYMYL寄りに扱う**（例：中小企業の投資判断を促す記事）

## 3. 記事の構造設計

```
タイトル（クエリの答えが分かる）
├ 導入：読者の痛み → この記事で解決すること → 結論の先出し
├ H2: 結論／全体像       ← 検索意図への直接回答をここで完結させる
├ H2: 根拠・詳細         ← 一次データ、手順、比較表
├ H2: 具体例／実践       ← 実際のケース、失敗例
├ H2: よくある疑問       ← PAAと実際の質問から
└ 締め：次の一歩（内部リンク／CTA）
```

**原則:**
- **答えを先に出す。** 冒頭2〜3文で結論を書く。前置きで引っ張らない（AI検索の抜き出し対象にもなる → `06-ai-search-geo.md`）
- 1見出し＝1つの問いに答える。見出しだけ読んで内容が分かる状態にする
- H1は1つ。H2→H3の階層を飛ばさない
- 表・箇条書き・番号手順を使い、スキャンできる形にする
- 画像には内容を説明するalt属性を付ける（装飾画像は空alt）
- 冗長な文字数稼ぎをしない。**必要十分が最短**

## 4. タイトル・ディスクリプション・見出し

**タイトル（title要素）**
- 主要キーワードを自然に、なるべく前方に
- 日本語で30字前後を目安（表示幅はデバイスで変わる。文字数は目安であって規則ではない）
- ページごとに固有。テンプレの使い回しで重複させない
- クリックされる要素（数字・具体性・ベネフィット・意外性）を入れる。ただし内容と乖離させない（釣りタイトルは滞在時間で跳ね返る）
- Googleはタイトルを書き換えることがある。書き換えられるのは、内容と乖離・長すぎ・キーワード詰め込みのとき

**メタディスクリプション**
- 直接のランキング要因ではないが、**CTRを通じて成果に効く**
- 80〜120字程度で、クエリの答えと読む理由を書く。未設定だとGoogleが本文から抜粋する
- キーワードを詰め込まない

**見出し**
- 見出しにキーワードを入れるのは自然な範囲で。**見出しの主目的は構造の提示**
- 「まとめ」だけの見出しは情報量ゼロ。何をまとめたか書く

## 5. 本文の書き方（SEO観点の作法）

**やること**
- 検索者が使う語彙で書く（社内用語・業界用語は初出で説明）
- 同義語・関連語を自然に含める（エンティティの理解を助ける）
- 数字・固有名詞・日付を具体的に書く
- 出典を本文中でリンクする。孫引きせず一次情報に当たる
- 更新したら更新日と更新内容を明示する

**やらないこと**
- キーワードの詰め込み（キーワード出現率という指標は追わない。Googleは密度で評価していない）
- 隠しテキスト、背景と同色の文字、CSSで隠した見出し
- 他サイトの言い換えだけの記事（Information Gainがゼロ）
- 目次だけ立派で中身が薄い「網羅風」記事
- 誇大表現、根拠のない最上級表現（景表法・薬機法にも触れる）

## 6. Information Gain（情報付加価値）

**「既存の上位10件を全部読んだ人が、この記事から新しく得るものは何か」に一文で答えられないなら、公開しない。**

情報付加価値の作り方:
- 自社データの公開（顧客数、平均値、Before/After、失敗率）
- 独自の検証・実測（自分で試した結果を数字と日付で）
- 独自の調査（アンケート、ヒアリング、現場観察）
- 既存情報の再構造化（散在する情報を判断できる形に整理した比較表・意思決定フロー）
- 現場の暗黙知（教科書に載っていないつまずきポイント）
- 反論・別解（通説に対する条件付きの否定）

## 7. AI生成コンテンツの扱い

Googleの立場は「**AI生成かどうかではなく、検索順位操作を主目的とした量産かどうか**」。人が書いても量産の劣化コンテンツはスパム扱いになる。

**安全な使い方:**
- リサーチ、構成の叩き、表現の推敲、要約、校正
- **一次情報・検証・判断は人間が入れる**
- 事実は必ず裏取りする（AIの出力をそのまま公開しない）
- 公開前に人の目で通す責任者を決める

**危険な使い方:**
- キーワード差し替えの量産、他サイトのAI言い換え、実体のない体験談の捏造
- 監修していないのに監修者名を載せる（Trustの致命傷）

## 8. リライト手順

1. **対象選定**（GSCで4軸）：クリック減少／順位下落トレンド／検索意図とのズレ／情報の陳腐化。
   最優先は「**表示回数はあるのにクリックが少ない**」「**11〜20位で停滞**」の記事。
2. **原因の特定**（先に決める。ここを飛ばすと作業が散る）
   - CTRが低い → タイトル・ディスクリプション・SERPでの見え方
   - 順位が低い → 内容の網羅性・一次情報・被リンク・内部リンク
   - 直帰が高い → 導入と検索意図の一致、ページ速度、可読性
   - 表示回数ごと減少 → 検索需要の減少／SERP構造の変化／サイト全体の評価低下
3. **現在のSERPを再観察**：意図が変わっていないかを最初に確認。**意図が変わっていたら部分修正では戻らない。作り直す**
4. **改修**：
   - 検索意図に対する答えを冒頭に移す
   - 不足トピックを追加（上位が全部答えていて自分だけ無い項目）
   - 古い数字・仕様・スクショを更新
   - 一次情報を足す（ここが最も効く）
   - 内部リンクを見直す（関連記事から／へ）
   - 構造化データを追加・修正
   - **不要になった記述を削る**（追記だけの肥大化は可読性を殺す）
5. **記録**：変更日・変更点・対象KWの当時の順位を残す
6. **判定**：最低4週間、コアアップデート中なら終了後まで待つ。同時に複数の変更を入れた記事は原因分析ができない点を意識する

## 9. コンテンツの棚卸し

全記事を4分類する。

| 判定 | 条件 | アクション |
|---|---|---|
| Keep | 流入・CVがある | 定期更新 |
| Improve | 表示はあるが順位・CTRが低い | リライト（優先） |
| Merge | 意図が重複、単体では弱い | 統合し301リダイレクト |
| Remove | 流入ゼロ、役割終了、情報が有害 | 削除＋適切なリダイレクト。行き先が無ければ410 |

**注意:** 「低品質ページを消せば全体が上がる」は条件付きの話。**流入が無いだけの正確なページを機械的に消さない**。判断基準は「ユーザーの役に立つか」。
