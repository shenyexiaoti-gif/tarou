## 1. 何が変わったか

- Googleの検索結果でAIによる要約（AI Overviews）が表示されるクエリが大きく増え、**上位表示＝クリック ではなくなった**。AI要約が出るクエリでは上位のCTRが顕著に落ちるという観測が一般的
- 一方で、**AI要約の中で引用（citation）されること**が新しい可視性の通貨になった
- ChatGPT / Perplexity / Gemini / Claude 経由の流入は量は小さいが、**検討が進んだ状態で来るためCVRが高い**という報告が多い

**前提:** これは従来SEOの置き換えではなく**上乗せ**。AIはインデックスされ、信頼でき、構造化されたページから引用する。土台が無ければGEO施策は空振りする。

## 2. 用語整理

| 用語 | 意味 |
|---|---|
| SEO | 検索エンジンでの可視性最適化（土台） |
| AEO（Answer Engine Optimization） | 質問に対する直接の答えとして採用されるための最適化 |
| GEO（Generative Engine Optimization） | 生成AIの回答内で引用・参照されるための最適化 |
| LLMO | 上記のLLM文脈での総称（日本で使われることが多い） |
| AI Overviews / AI Mode | Google検索内のAI要約／AI対話モード |

呼び方は乱立している。**中身は「機械が読み取り、要約し、出典として選びやすい情報を出す」ことで共通**。

## 3. AI検索がソースを選ぶ仕組み（動作モデル）

だいたい以下の流れで動く。各段階に対策が対応する。

```
1. クエリの分解（1つの質問を複数のサブクエリに展開）
        ↓  → 対策：問いの分解単位ごとに答えを用意する
2. 検索・取得（インデックス／リアルタイム検索から候補を集める）
        ↓  → 対策：インデックスされていること、クロール可能であること
3. 抽出（各ページから該当箇所を切り出す）
        ↓  → 対策：見出し直下で完結する答え、明快な構造、SSR
4. 統合・生成（複数ソースを合成して回答を作る）
        ↓  → 対策：他ソースと矛盾しない事実、独自データ
5. 引用の選択（ごく少数のソースだけを出典表示）
             → 対策：権威・鮮度・一次情報・エンティティの明確さ
```

**5で選ばれなければ露出はゼロ。** 取得されても引用されないことが普通に起きる。

## 4. 引用されるための5本柱

1. **抽出しやすい構造**：質問形式の見出し ＋ 直下に完結した答え（40〜60字程度の1〜2文）→ その後に詳細
2. **構造化データ**：Organization / Article / Person / Product / Breadcrumb。エンティティ関係を `@id` で明示（→ `04-structured-data.md`）
3. **エンティティの一貫性**：社名・著者名・専門領域が、サイト内外で同じ表記・同じ文脈で語られている
4. **第三者からの言及の footprint**：レビューサイト、業界メディア、比較記事、コミュニティ（Reddit・知恵袋・note・Qiita等のUGCはAIに参照されやすい）
5. **コンテンツ要因**：一次データ、明示的な数値、日付、出典、専門家の引用。**「引用したくなる形の事実」を持っていること**

## 5. コンテンツの書き方（抽出されやすい形）

**書式**
- H2/H3を**そのままユーザーの質問文**にする（「◯◯とは何か」「◯◯はいくらかかるか」）
- 見出し直下の第1文で答え切る（結論の先出し。前置きゼロ）
- 定義・数値・手順は**箇条書きと表**にする（散文の中に埋めない）
- 1トピック1ブロックで自己完結させる。**前の段落を読まないと意味が通らない書き方をしない**（チャンク単位で切り出されるため）
- 数値には必ず単位・条件・時点を添える（「平均30%削減（2026年4月、当社12社の導入前後比較）」）
- 更新日を明示する。鮮度は引用選択に影響する（特にPerplexity系）

**内容**
- 一次情報（→ `02-content-eeat.md` §6）。AIが他所から取れる一般論は引用する理由がない
- 比較・選定基準・「どんな人に向くか」を明示（AIは推薦の根拠を欲しがる）
- FAQセクションは**リッチリザルト目的ではなく機械可読性目的**で有効（FAQリッチリザルト自体は廃止済み → `04-structured-data.md`）
- 用語の定義を明示的に書く（「AとはBである」の形は抽出されやすい）

## 6. 技術要件

- **SSR / 静的HTML**：多くのAIクローラーはJavaScriptを実行しない。**初期HTMLに本文が無いページは引用対象にならない**
- robots.txtでAIクローラーをブロックしていないか確認（ブロックしたら引用もされない）
- 主要なユーザーエージェント例：`GPTBot`、`OAI-SearchBot`、`ChatGPT-User`、`PerplexityBot`、`ClaudeBot`、`Google-Extended`（GoogleのAI学習用。**ブロックしてもGoogle検索のインデックスには影響しないが、AI関連の扱いに影響し得る**）
- 表示速度、モバイル対応、HTTPSは前提
- ページ内のテキストを画像に埋め込まない（読めない）

**方針判断:** 学習に使われたくないコンテンツと、引用されたいコンテンツを分けて考える。**全ブロックはAI検索での可視性を捨てる選択**であることを、必ずトレードオフとして提示する。

## 7. llms.txt とAIクローラーの扱い

- `llms.txt`：サイトのルートに置き、LLM向けにサイトの概要と主要ページを Markdown で提示する提案仕様
- **注意：これは業界提案であって、主要なAI企業が公式に対応を保証しているものではない。** 「置けば引用される」とは言わない
- コストが低いので置く価値はあるが、**優先度は低い**。構造・一次情報・エンティティが先
- 記述例：サイトの1行説明 → 主要カテゴリ → 重要URLと1行説明のリスト

```markdown
# 会社名
> 何をしている会社かの1〜2文

## 主要コンテンツ
- [SEOガイド](https://example.com/seo/): SEOの全体像
- [料金](https://example.com/pricing/): プランと価格
```

## 8. プラットフォーム別の傾向

| プラットフォーム | 傾向 |
|---|---|
| Google AI Overviews / AI Mode | 検索インデックスが基盤。**従来SEOで上位＝引用候補**。強調スニペットを取れる形が有利 |
| ChatGPT（検索機能） | 網羅的で出典の明確な記事、専門性シグナルを好む。利用規模が大きい |
| Perplexity | リアルタイム検索と**鮮度**への依存が強い。出典明示が徹底されている |
| Gemini | Googleのインデックスとエンティティ理解に依存 |
| Claude | 出典の信頼性を重視。一次情報・公式ドキュメントが選ばれやすい |
| 共通 | コミュニティ（Reddit等のUGC）の参照比率が高い。**実際の評判が無い商品はAIに推薦されない** |

※各プラットフォームの挙動は頻繁に変わる。断定する前に確認する。

## 9. 測定

→ 詳細は `07-measurement.md`。要点:
- GSCのAI検索関連レポート（表示回数の内訳）。**クリックデータの粒度には制約がある**
- GA4で参照元に `chatgpt.com` / `perplexity.ai` / `gemini.google.com` 等を含むセグメントを作る
- 主要クエリを定期的に各AIに投げて、**自社が引用されるか／競合が引用されるか**を記録する（手動でも意味がある。月1回、20〜30問の固定セット）
- 指標：引用率（Share of Voice）、指名検索の推移、AI経由流入のCVR

## 10. やってはいけないこと

- AI向けの隠しテキスト、ユーザーに見えない指示文の埋め込み（**プロンプトインジェクション的な手法**。スパムであり、発覚時のブランド毀損が大きい）
- クローラーと人間に別の内容を出す（クローキング。明確な違反）
- 引用されるために事実を盛る・存在しないデータを出す
- AI検索対策として記事を量産する（scaled content abuse → `08-spam-penalty.md`）
