# SEO実務OS

SEOの全領域を扱う。**SKILL.mdは地図。実作業は必ず該当のreferenceを読んでから始める。**

## 0. 起動したらまずやること

1. 相手の状況を1行で確定する（新規サイト／既存サイトの改善／単発記事／順位下落の緊急対応）
2. 下のルーティング表で該当ファイルを選び、**読んでから**手を動かす
3. 数字・仕様・アルゴリズム名を出す前に「鮮度ポリシー」（§3）を通す

## 2. 大前提（全施策の判断基準）

1. **検索意図が最上位。** 意図を外した記事は、技術的に完璧でも上がらない。キーワードではなく「そのクエリの裏にある未解決の問い」に答える。
2. **一次情報が唯一の差別化。** 実データ・実体験・独自の検証・現場の数字。生成AIが量産できる一般論は、もはや価値をつけない（Information Gain＝既存の検索結果に対して新しい情報を足せているか）。
3. **信頼（Trust）がE-E-A-Tの中心。** 経験・専門性・権威性は全部Trustを支えるための部品。運営者情報・執筆者情報・出典・更新日が曖昧なサイトは、内容が良くても評価されない。
4. **クリックされない上位は成果にならない。** AI Overviewsが出るクエリでは1位でもCTRが大きく落ちる。「順位」ではなく「指名検索・引用・コンバージョン」を成果指標に置く（→ `07-measurement.md`）。
5. **小手先の操作は必ず負ける。** 自動生成の量産・被リンク購入・他人のドメインの間借り・期限切れドメインの再利用は、スパムポリシーで明示的に禁止されている（→ `08-spam-penalty.md`）。

## 3. 鮮度ポリシー（絶対に守る）

SEOは仕様変更が速い。**以下のカテゴリの事実は、断定する前に必ずWeb検索でその日の状態を確認する。**

- Googleのコアアップデート／スパムアップデートの実施状況と対象
- サポートされるリッチリザルトの種類（**FAQ・HowTo系は縮小・廃止の流れ**。実装前に必ず確認）
- Core Web Vitalsの指標と閾値（FID→INPのように指標そのものが入れ替わる）
- Search Console／GA4のレポート項目（AI検索系レポートは追加・変更が続いている）
- AI Overviews／AI Modeの表示率・CTR影響などの統計値
- 各種SEOツールの料金・機能

数字を出すときは **「◯年◯月時点」「出典元」** を必ず添える。出典が思い出せない数字は使わない。
本スキル内の数値は執筆時点（2026年8月）のスナップショットであり、**参照した瞬間に古い可能性がある前提で扱う**。

## 4. 標準ワークフロー

### A. 新規記事をSEOで設計する
1. `01-strategy-keyword.md` → キーワード候補・検索意図の分類・クラスタ内での役割を決める
2. 実際に検索してSERPを観察（上位10件の型／AI Overviewの有無／PAA／SERP機能）
3. `02-content-eeat.md` → 見出し構成・一次情報の差し込み位置・E-E-A-Tシグナルを設計
4. 執筆（太郎課長のコンテンツなら `x-article-writing` に接続。§6参照）
5. `09-checklists.md` の「公開前チェックリスト」を通す
6. `04-structured-data.md` → 必要な構造化データを実装
7. `07-measurement.md` → 計測の初期値を記録（公開日・対象KW・初期順位）

### B. 既存記事をリライトする
1. `07-measurement.md` → GSCで対象記事を選定（クリック減・順位下落・意図ズレ・情報の陳腐化の4軸）
2. 現在の1〜10位を再観察。**検索意図が変わっていないか**を最初に疑う
3. `02-content-eeat.md`「リライト手順」に従う（追記だけで済ませない。構成ごと組み替える判断も持つ）
4. 更新日を明示し、変更点を記録。効果判定は最低4週間
5. リライトで順位が落ちたら、変更を分解して原因を特定（一度に全部変えない）

### C. サイト全体を監査する
`09-checklists.md` の「サイト監査チェックリスト」を上から実行。指摘は必ず **影響度×工数** で優先順位をつけて出す。指摘の羅列だけで終わらせない。

### D. 順位・流入が落ちた
`08-spam-penalty.md` の「下落の切り分けフロー」を実行。
**手動対策 → 技術事故 → コアアップデート → 季節性／SERP構造変化 → 競合の伸長** の順で潰す。原因を特定する前に施策を打たない。

### E. AI検索で引用されたい
`06-ai-search-geo.md`。従来SEOの上に乗る施策であって、置き換えではない。土台（インデックス・信頼性・構造）が無いままGEO施策だけやっても引用されない。

## 5. 出力の作法

- **必ず優先順位をつける。** 「やるべきこと20個」は成果につながらない。Top3を先に出し、残りは後段に。
- **施策には必ず「なぜ効くか」と「どう測るか」を添える。** 効果測定できない施策は提案しない。
- **断定と推測を書き分ける。** Google公式が明言していることと、業界の観測・通説を混ぜない。
- 相手が非エンジニアなら、実装案は「誰に何を依頼すればいいか」の粒度まで落とす。
- 順位保証・確実に上がるといった断定はしない。SEOは確率を上げる仕事。

## 6. 他スキルとの役割分担

| スキル | 担当 |
|---|---|
| **seo（本スキル）** | 検索エンジン・AI検索に「見つけられ、選ばれる」ための設計と診断 |
| `x-article-writing` | 太郎課長の文体・型・執筆手順。**書く作業本体はこちら** |
| `x-article-check` / `thumbnail-title-hook-check` | 公開前の品質関所（読者視点） |
| `taro-strategy` / `taro-materials` | 何者として何を売るか／フック・エピソードの素材 |
| `smb-ai-topdown` | 中小企業×AIのSEO記事量産型 |
| `masking-guard` | 公開前の機密・個人情報マスキング |

**連携ルール:** 太郎課長名義の記事では、SEOは「キーワード設計・見出し構成・内部リンク・構造化データ」までを担当し、**文体と型は必ず `x-article-writing` に渡す**。SEOの都合で文体を平板にしない。検索エンジンに最適化して読者に読まれない記事は失敗。
